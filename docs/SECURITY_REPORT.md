## 一、项目概述

滨海小镇（bhxz）是一个基于 Flask + DuckDB 的 Minecraft 服务器管理网站，提供论坛讨论、指南管理、大喇叭音频上传/播放、管理员控制台、脚本执行、定时任务、邮件广播、数据库备份等交互式功能。项目采用 Python 后端（Flask）+ 前端（Jinja2 模板 + Tailwind CSS + 原生 JavaScript）架构，无前后端分离。

***

## 二、交互式服务安全检查表逐项评估

### 2.1 认证与身份管理

| 检查项          | 状态          | 说明                                                                                     |
| ------------ | ----------- | -------------------------------------------------------------------------------------- |
| 密码使用强哈希算法存储  | ✅ **通过**    | 采用 `werkzeug.security.generate_password_hash(method='scrypt')`，scrypt 为内存硬抗 ASIC 的现代算法 |
| 兼容哈希已做升级处理   | ⚠️ **部分通过** | 登录成功时自动升级旧 SHA-256 无盐哈希，但数据库若仍存旧哈希，泄露后可被彩虹表破解                                          |
| 密码强度校验       | ⚠️ **部分通过** | 仅检查长度 ≥8 且含至少一个字母，缺少大写/数字/特殊字符要求，缺少弱密码字典检查                                             |
| 账户锁定机制       | ❌ **未通过**   | `MAX_LOGIN_ATTEMPTS=5` 和 `LOGIN_LOCKOUT_TIME=1800` 已配置但**未实现**，攻击者可无限暴力破解              |
| 登录速率限制       | ⚠️ **部分通过** | 10 次/分钟/IP，但仅基于 IP 粒度，NAT 环境可能误伤；服务重启后速率记录丢失                                           |
| 注册速率限制       | ✅ **通过**    | 5 次/分钟/IP，配合图形验证码双重防护                                                                  |
| 图形验证码        | ✅ **通过**    | 注册/登录/找回密码均使用图形验证码，不区分大小写，一次性消费防重放                                                     |
| 找回密码速率限制     | ❌ **未通过**   | 虽需双重验证，但无独立 IP 速率限制                                                                    |
| Session 签名密钥 | ❌ **未通过**   | `SECRET_KEY` 硬编码在 `config.py` 中，所有部署实例共享同一密钥，泄露后可伪造任意用户 session                        |

## 三、风险发现与评级

### 3.1 风险等级说明

| 等级    | 定义                  | 响应时限          |
| ----- | ------------------- | ------------- |
| 🔴 严重 | 可直接导致数据泄露、系统沦陷、权限绕过 | 应立即修复         |
| 🟠 高危 | 攻击面大、利用难度低，可造成较大危害  | 应尽快修复（1-2 周内） |
| 🟡 中危 | 有一定危害但需特定条件或较高利用难度  | 应在下次迭代中修复     |
| 🟢 低危 | 危害有限或利用条件苛刻         | 可列为后续优化项      |

### 3.2 风险清单

#### 🔴 严重（3 项）

| 编号       | 风险                  | 影响                                                                             | 涉及文件                  |
| -------- | ------------------- | ------------------------------------------------------------------------------ | --------------------- |
| **R-01** | **CSRF 保护完全缺失**     | 全站所有 POST 路由（改密、改邮箱、删账号、登录、注册、管理员操作）均无 CSRF token。攻击者可构造恶意页面，在受害者登录状态下静默执行操作   | 全站所有 POST 路由          |
| **R-02** | **更新机制 SSL 证书验证禁用** | `ssl.CERT_NONE` 导致所有 HTTPS 请求（含 ZIP 下载）不验证证书，任何人可 MITM 替换下载内容为恶意代码，构成完整供应链攻击链  | `services/updater.py` |
| **R-03** | **SECRET\_KEY 硬编码** | 所有部署实例使用相同密钥 `mc_server_site_random_secret_key_2024`，泄露后可伪造任意用户 session cookie | `config.py`           |

#### 🟠 高危（4 项）

| 编号       | 风险                           | 影响                                                                          | 涉及文件                                                    |
| -------- | ---------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------- |
| **R-04** | **账户锁定机制未实现**                | `MAX_LOGIN_ATTEMPTS=5` 已配置但不生效，攻击者可对任意账户进行无限制密码枚举                           | `config.py` / `user_service.py`                         |
| **R-05** | **更新机制无代码签名/完整性校验**          | 下载的 ZIP 包无 SHA256 哈希或 GPG 签名校验，配合 R-02，攻击者可推送任意恶意代码                         | `services/updater.py`                                   |
| **R-06** | **管理员脚本命令执行无沙箱**             | `cmd_runner.py` 以 `shell=True` 执行管理员输入的任意命令，管理员账户沦陷即全系统沦陷                   | `routes/script/execution.py` / `services/cmd_runner.py` |
| **R-07** | **Session 过期时间未配置（默认 31 天）** | `PERMANENT_SESSION_LIFETIME` 未设置，实际使用 Flask 默认 31 天，登录态长期有效，增加 session 劫持风险 | `app.py`                                                |

#### 🟡 中危（8 项）

| 编号       | 风险                      | 影响                                                 | 涉及文件                                                      |
| -------- | ----------------------- | -------------------------------------------------- | --------------------------------------------------------- |
| **R-08** | **文件上传无大小限制**           | 附件和音频上传可耗尽磁盘空间，导致拒绝服务                              | `services/attachment_service.py` / `routes/main/music.py` |
| **R-09** | **音频上传无内容魔数校验**         | 仅检查扩展名白名单，不验证文件头，可上传伪装为音频的其他文件                     | `services/music_service.py`                               |
| **R-10** | **终端输出无转义序列过滤**         | 恶意进程可注入终端控制序列（清屏、伪造输出、隐藏光标等），诱导管理员执行危险操作           | `services/terminal/session.py`                            |
| **R-11** | **IP 地址可伪造（无信任代理白名单）**  | 客户端可注入 `X-Forwarded-For` 等头部伪造 IP 地址，绕过 IP 速率限制和审计 | `services/ip.py`                                          |
| **R-12** | **邮箱（PII）记录日志**         | 注册和改邮箱时记录完整邮箱地址，违反隐私合规要求                           | `services/user_service.py`                                |
| **R-13** | **密码强度校验偏弱**            | 仅检查长度 ≥8 + 含字母，无大写/数字/特殊字符要求，无弱密码字典检查              | `core/auth.py`                                            |
| **R-14** | **Secure cookie 条件性启用** | HTTP 部署下 session cookie 无 Secure 标志，明文传输可被中间人劫持    | `app.py`                                                  |
| **R-15** | **找回密码无独立速率限制**         | 虽需双重验证但无 IP 级别频率限制，可被批量枚举                          | `services/user_service.py`                                |

#### 🟢 低危（8 项）

| 编号       | 风险                                        | 影响                                                                      | 涉及文件                             |
| -------- | ----------------------------------------- | ----------------------------------------------------------------------- | -------------------------------- |
| **R-16** | **SHA-256 兼容哈希无盐**                        | 旧格式无盐 SHA-256 哈希可被彩虹表快速破解                                               | `core/auth.py`                   |
| **R-17** | **注册后** **`group_code_verified`** **未清除** | 同一浏览器 session 中可重复使用已验证的群码状态                                            | `routes/main/auth.py`            |
| **R-18** | **速率限制器无自动清理**                            | `cleanup_expired()` 未定时调用，长时间运行有轻微内存泄漏                                  | `services/ratelimit.py`          |
| **R-19** | **部分数据库连接未使用 context manager**            | 异常分支可能未关闭连接，但 DuckDB 非网络数据库，风险有限                                        | `services/user_service.py`       |
| **R-20** | **授权检查不一致**                               | 部分路由使用 `@admin_required`，部分手动检查，新增路由时易遗漏                                | `routes/admin/*.py`              |
| **R-21** | **授权失败无审计日志**                             | `abort(403)` 触发时无日志记录，难以追踪攻击尝试                                          | `routes/admin/*.py`              |
| **R-22** | **附件清理函数路径遍历风险**                          | 若数据库存储恶意 `fname` 可删除任意文件，但 `save_attachments()` 已使用 `secure_filename()` | `services/attachment_service.py` |
| **R-23** | **备份文件明文存储**                              | 备份文件无加密，拥有文件系统权限即可读取全部数据                                                | `services/backup/manager.py`     |

## 六、安全架构优势

尽管存在上述风险，项目在以下方面表现出良好的安全实践：

1. **密码哈希**：使用 `scrypt`（现代内存硬哈希算法），优于常见的 `bcrypt` 和 `pbkdf2`
2. **SQL 注入防护**：全站统一使用参数化查询，未发现用户可控的 SQL 拼接
3. **响应头安全**：CSP、HSTS、X-Frame-Options、X-Content-Type-Options、Referrer-Policy、Permissions-Policy 均正确配置
4. **富文本清洗**：广播邮件 HTML 白名单清洗到位，仅允许安全标签和属性
5. **路径遍历防护**：公开文件服务和 HLS 分片服务均有双重路径校验
6. **Session 管理**：`session.clear()` 防固定攻击、`HttpOnly` + `SameSite=Lax` 防跨站
7. **图形验证码**：一次性消费、不区分大小写、防重放
8. **速率限制**：注册/登录/邮箱验证码均有限频
9. **重定向校验**：`_is_safe_redirect_url()` 防开放重定向
10. **更新保护路径**：关键文件（数据库、上传文件、配置）不受更新覆盖
